# 实验 T2：类无关候选补漏（负结果）

**日期**：2026-10-02
**目的**：检验 §4.5 给出的唯一出路——"引入类无关候选来源以补全漏检"——是否真的能兑现
FN oracle 残留的 **+0.97** 点。
**结论**：**不能**。20 个配置全部未达事先约定的判据（dev ΔSα ≥ +0.005），最好为 +0.07 点
（噪声量级），其余全部显著为负（最差 -37.4 点）。本文件完整记录实现、命令、全部数字与失败机理。

---

## 1. 判据（事先约定，未事后修改）

dev 50 上，T2 最优配置相对"仅主分支（PRISM 完整配置）"的 dev Sα 增益 **< +0.005** →
判定类无关候选无净收益，停止在测试集上追加 T2 配置，并把负结果写入论文边界讨论。

- dev 50 ⊂ ORSSD 训练集，与校准器训练集重叠 → dev 数值偏乐观，**只用于选配置，不作为成绩**。
- 本次 20 个配置的 dev 主分支基线为 **Sα = 0.9162**，与 T1 dev 记录（0.9042，含旧版
  融合细节差异）一致，说明主分支实现与既有最好配置对齐。

## 2. 实现

| 脚本 | 作用 |
|---|---|
| `scripts/build_gridbank.py` | 类无关粗网格点 → SAM2 候选掩码，packbits 压缩缓存到磁盘 |
| `scripts/predict_t2.py` | 一次图像编码内解码主提示 + 补漏候选，七道闸门筛选后融合出图 |
| `scripts/t2_sweep.py` | dev 50 超参扫描，自动评测并写 `runs/mllm/t2_sweep.json` |
| `scripts/t2_reachability.py` | 几何可达性硬判据（无需 GPU、无需候选库） |
| `scripts/t2_diag_missed.py` | 漏检连通域 vs 候选覆盖的直接测量 |
| `scripts/run_t2.py` | 全流程编排（阶段 A/B2/C/D） |
| `scripts/T2_dashboard.py` | 实时进度网页（`http://127.0.0.1:43121/`，静态快照 `paper/T2_进度.html`） |

**候选生成**：在归一化 [0,1000] 空间按 interval 切网格取格心，用单点正提示向 SAM2
（冻结 base+ 或校准器，`--cand_decoder`）索取 multimask 输出，按自报 score 取最优候选，
二值化（soft>0.5）后 packbits 存盘。实测 **0.209 s/图 编码 + 9.1 ms/点解码**（RTX 4060 8GB），
interval 64（256 点/图）全测试集 2999 张约 **26 分钟**、磁盘约 1.1 GB。

**候选筛选闸门**（全部只在候选侧生效，主分支保持与 `prism-ma25-ft` 一致，保证可对比）：

| 闸门 | 含义 |
|---|---|
| G1 | SAM2 自报 score ≥ `--cand_tau` |
| G2 | 候选掩码面积占比在 `[cand_area_min, cand_area_max]` 内 |
| G2c | 连通域面积占比 ≤ `--cand_comp_max` |
| G3 | 掩码贴边像素占比 ≤ `--cand_border_max`（越界膨胀守卫） |
| G4 | 与主掩码 IoU ≤ `--cand_dup_iou`（避免重复） |
| G5 | 连通域内 SAM2 logits 均值经 sigmoid 后 ≥ `--cand_core_p`（置信核心） |
| G6 | 连通域在主分支显著图上的概率均值 ≥ `--cand_sal_p`（显著性裁判） |

**融合**：候选侧先按连通域切分、逐块过闸门、块间 NMS，再 `S = max(S_primary, w · M_cand)`。

## 5. 失败机理

### 5.1 漏检目标的量级（`t2_reach.json`，全测试集 2999 张）

| 项 | 值 |
|---|---|
| GT 连通域总数 | 5031（ORSSD 324 / EORSSD 988 / ORSI-4199 3719） |
| 没有任何 MLLM 框碰到 | **486（9.7%）** |
| 漏检连通域面积占比 | 中位 **0.20%**、均值 1.10%、90 分位 1.8%、最大 53.1% |
| 已命中连通域面积占比 | 中位 2.30%、均值 8.5%、90 分位 28.5% |
| 漏检像素 / 全部 GT 前景像素 | **0.90%** |
| 面积 < 0.05% 的漏检连通域 | 142 / 486 |

→ 漏检是"**数量不少、面积极小**"的一类误差。oracle 的 +0.97 点正来自这些几乎不占前景面积的
小块；而 S-measure 对"干净背景上多出一块假前景"的惩罚远大于对"少一块 0.2% 小目标"的惩罚。

### 5.2 框形式在几何上不可达（`t2_reach.json` → `grid_rescue`）

漏检连通域包围盒面积 / 目标面积：中位 1.00、均值 1.39、90 分位 2.16。
以**任何**网格格心为中心、保持宽高比二分缩放到 IoU ≥ 0.5：

| 网格 | 可解漏检数 / 486 |
|---|---|
| interval 64（16×16） | **0** |
| interval 32（32×32） | **0** |
| interval 16（63×63） | **0** |

→ 因为多数漏检目标的掩码填充率低于 0.5，"包围盒"这一**形状**本身达不到 IoU 0.5。
漏检的根因不是"没找到位置"（网格点确实落在目标上，见 §5.3），而是**目标形状与框提示不匹配**
加上类别语义缺失。唯一的替代是用二值掩码（而非框）补，但那会触发 §5.4 的尺度失控。

### 5.3 位置其实是可达的（`t2_diag_missed.py`）

dev 50 上，网格候选掩码对漏检连通域的覆盖率 **100%**（i64 与 i32 均是）。
即"网格点落在目标上"不是瓶颈——瓶颈在落到之后得到的**掩码质量**。

### 5.4 点提示掩码的尺度系统性偏大

候选掩码来自 SAM2 的单点提示，它回答的是"这个点所在的连通区域是什么"，而不是"这里的显著
目标是什么"。冻结版与校准器版（`--cand_decoder`）表现一致地偏大：

| 图 | 主分支前景像素 | 加入候选后 | GT 前景像素 | 相对 GT 倍数 |
|---|---|---|---|---|
| ORSSD/0017 | 2 992 | 25 405（`m75`）/ 26 278（`m65`） | 3 122 | 8.1×～8.4× |
| ORSSD/0043 | 1 197 | 23 087（`m65`） | 1 144 | 20.2× |
| ORSSD/0065 | 31 567 | 183 814（`m75`）/ 183 819（`m65`） | 34 944 | 5.3× |

这是 Sα / MAE 崩塌的直接原因。**只有一个办法能把它拉回基线**：把 G6 显著度阈值提到 0.70，
即"只补主分支其实已经认出来的区域"——此时新增块降到 11～14 个、增益回到噪声量级（+0.07），
**T2 不再提供任何新信息**。这是一个有价值的自洽性检验：T2 的失败不是实现 bug，而是
"类无关信号无法区分显著与非显著"这一本质困难。

### 5.5 与论文中 oracle 的关系

`oracle-fn-ft`（用 GT 连通域框补漏）实测 **+0.97**，是"若补漏完美可达"的上界。
本次 T2 证明：在"零标注提示 + 冻结 SAM2"设定下，用**类无关**候选兑现该上界的路径被封死。
要兑现必须引入**语义级**候选来源（让 MLLM 显式枚举可能遗漏的实例，或训练显著目标先验），
而这会破坏"提示侧零标注"的定位——因此本文不采用，并在 §4.5 与 §5 中如实写明。

## 6. 实现过程中发现并修正的两个自身缺陷（如实记录）

1. **dev 图像清单错配**：`build_gridbank.py` 最初默认使用测试集提示库 `sam2_prompts.json`，
   而 dev 50 是 **ORSSD 训练集**图像（如 `0017.jpg` 只在 `Image-train` 存在）。两者命名集合
   不交，导致"待处理 0 张"并静默产出空候选库。已改为 `--bank` 必填并显式区分 `--split`。
2. **主分支基线被污染**：扫描中"仅主分支"配置最初写成"不加任何候选参数"，但
   `--cand_tau` 的默认值是 0.75，实际仍在加候选——得到的 0.6168 不是基线而是又一个 T2 配置，
   使全部 Δ 值失真。已改为显式 `--cand_tau 1.01`（不可能达到的阈值）。
   修正后主分支基线 0.9162，与 T1 dev 记录一致。

这两处都属于"会造成静默错误结果"的缺陷，记录在此以备复核。
