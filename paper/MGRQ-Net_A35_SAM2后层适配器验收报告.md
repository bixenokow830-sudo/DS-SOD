# MGRQ-Net A35 SAM2 后层适配器验收报告

## 1. 阶段结论

A35 已完成 `seed=42` 的严格训练和内部验证。工程状态为 **PASSED**，研究验收门为 **FAILED**，DeepSeek API 调用为 **0**。

A35 在干净 DeepSeek 候选条件下取得明显数值提升：相对 A34-R4，宏平均 Sα 从 0.836176 提高到 0.842685，增加 0.006510；MAE 从 0.030507 降低到 0.025294，改善 0.005213。但在冻结的高质量匹配提示视觉 oracle 中，Sα 从 0.827238 降至 0.818299，下降 0.008939；F_mean 和 E_mean 也同时下降。因此，当前提升不能被明确解释为 SAM2 视觉域表征增强，A35 暂不应进入最终模型，也不应直接作为 A36 的新底座。

## 4. 视觉 oracle 对照

### 4.1 协议

视觉 oracle 只保留与 GT 组件 IoU≥0.5 的原始高质量候选，并将其几何框替换为对应 GT 组件框；短语、候选身份和其余模型流程保持不变。GT 只用于构造该受控对照，不参与测试集选择或最终推理。

- 验证图像：400 张；
- 存在至少一个匹配提示的图像：354 张；
- 匹配组件：555 个；
- A34-R4 和 A35 使用完全相同的 oracle 输入。

### 4.2 结果

| 配置 | Sα | F_max | F_mean | E_max | E_mean | MAE |
|---|---:|---:|---:|---:|---:|---:|
| A34-R4 oracle | 0.827238 | 0.785297 | 0.653427 | 0.985517 | 0.828768 | 0.035227 |
| A35 oracle | 0.818299 | 0.779797 | 0.625075 | 0.978905 | 0.799985 | 0.033240 |
| A35−A34-R4 | **−0.008939** | −0.005500 | −0.028353 | −0.006611 | −0.028783 | **−0.001987** |

A35 的 oracle MAE 改善，但 Sα、F_max、F_mean、E_max 和 E_mean 全部下降。输出更保守、平均背景误差更小，却损失了结构完整性和阈值曲线表现。根据预先冻结的判据，不能把这种结果认定为视觉域适配成功。

## 6. 原因判断

当前证据更支持以下解释：

1. 联合训练阶段主要优化了训练候选分布下的解码和概率校准，因此干净候选 MAE 大幅改善。
2. 适配器与解码器同时更新，无法把干净集提升单独归因于视觉适配器；335.82 万个解码器参数远多于 3.37 万个适配器参数。
3. oracle 条件下 F_mean 和 E_mean 明显下降，说明模型对高质量提示产生了更窄或更保守的响应，结构覆盖能力反而下降。
4. 训练末段窗口损失没有呈现稳定低于首段的趋势，说明 1+2 epoch 的联合配方可能已偏离视觉适配目标。
5. 本次适配器作用于 Hiera 输出后的缓存特征，而非 Hiera 内部最后 stage；其表达范围有限，不能据此否定所有 SAM2 内部适配方案。

## 7. 阶段决策与下一步

A35 不应直接进入最终模型，也不应立刻以其为底座执行 A36。建议先执行成本较低的 **A35-R1 归因审计**，不重新调用 API：

1. 恢复 epoch 1 的“仅适配器”检查点，对干净候选和同一 oracle 重新评测；
2. 将 epoch 1、epoch 3 与 A34-R4 并列，区分适配器贡献和解码器联合训练贡献；
3. 若 epoch 1 的 oracle Sα 提高，则保留适配器、缩小或取消解码器联合更新；
4. 若 epoch 1 仍不能提高 oracle Sα，则停止 A35 分支，以 A34-R4 作为 A36 的底座；
5. 不允许仅凭干净候选的 +0.006510 Sα 宣称“视觉域适配有效”。

因此当前门禁为：

`NO-GO_A36_FROM_A35；先执行 A35-R1 归因审计。`
