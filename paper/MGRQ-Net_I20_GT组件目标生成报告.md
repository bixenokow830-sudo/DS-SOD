# MGRQ-Net I20｜GT组件目标生成报告

## 1. 执行结论

I20 已完成并通过验收（`PASSED`）。本阶段将 M01-R1 严格去重清单中的整图显著性 GT 转换为可供 MGRQ-Net 组件级查询监督使用的目标：组件标签图、边界标签图、包围框、面积、质心及边界元数据。

本阶段不调用 DeepSeek API，不使用 GPU，也不读取官方测试集 GT。

## 2. 输入与冻结规则

| 项目 | 冻结值 |
|---|---|
| 输入清单 | `ds_sod/banks/mgrq/manifests/d14_strict_manifest.json` |
| 样本数 | 3328（train 2928、dev 400） |
| 数据集 | EORSSD 972、ORSI4199 1939、ORSSD 417 |
| 前景阈值 | 灰度值 `> 128` |
| 连通性 | 8 邻域 |
| 最小组件面积 | 4 像素，即保留 `area >= 4` |
| 包围框格式 | 像素坐标 `[x0, y0, x1, y1)`，右下边界不包含 |
| 组件标签类型 | `uint16` |
| 边界定义 | 组件掩码减去 3×3 二值腐蚀结果，图像外按 0 处理 |
| 相连标注处理 | 不拆分；一个连通域保持为一个组件 |

面积阈值 4 是在完整严格训练/开发清单统计后确定的。原始 6556 个组件中，小于 4 像素的组件为 739 个，只占 778 个前景像素；过滤后保留 5817 个组件和 58,983,744 个前景像素。该阈值主要清除孤立标注噪声，同时最大限度保留真实小目标。

## 3. 输出格式

组件目标库位于：

```text
ds_sod/banks/mgrq/gt_components/v1/
├── config.json
├── index.json
└── targets/
    ├── train/*.npz
    └── dev/*.npz
```

每个 `.npz` 文件包含：

- `label_map`：0 为背景，正整数为组件 ID；
- `boundary_map`：0 为非边界，正整数与所属组件 ID 一致。

`index.json` 为每个组件记录：`mask_ref`、`boundary_ref`、包围框、像素面积、面积比例、质心、边界像素数及是否接触图像边缘。文件还保存目标数组哈希，以便训练前检查损坏或错配。

## 5. 数据增强同步规则

实现支持 `identity`、水平翻转、垂直翻转、逆时针 90°、180°和顺时针 90°。增强时先对标签图和边界图执行完全相同的几何变换，再重新计算包围框、面积、质心、边界像素数和图像边缘接触状态，避免只变换图像而保留旧组件坐标。

## 8. 边界与后续步骤

本阶段严格遵守“不拆分已有连通标注”的规则。因此，若两个真实目标在 GT 中相互接触，它们仍会作为一个组件监督，这是当前组件定义的明确边界，不应在训练中解释为实例分割标签。

I20 只构造监督目标，不改变基础显著性分割标签，也不引入 API 伪标签。下一阶段 I21 可在此组件目标库上实现组件查询编码与批处理接口，并验证增强后的组件监督能稳定进入训练数据流。
