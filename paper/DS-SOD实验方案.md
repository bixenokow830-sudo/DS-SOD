## 第 1 章 研究假设（先定假设，再做实验）

论文的每个实验都必须服务于一条假设。DS-SOD 的假设清单：

| 编号 | 假设 | 对应实验（第几章） |
|------|------|-------------------|
| H1 | LLM 语义先验能提升 ORSI-SOD 精度 | 阶段2消融、主实验（第6章） |
| H2 | "会看会想的 LLM 语义"优于"静态 CLIP 文本" | 消融 #2 vs #3（第6章） |
| H3 | 类别/外观/难例三类语义信息各自都有贡献 | 消融 #3/#4/#5（第6章） |
| H4 | 语义引导的迭代修正优于 IPDiff 式盲迭代 | 消融 #8（第6章） |
| H5 | 增益集中在语义难例（低对比/阴影/同谱异物等） | 场景分组评测（第7章） |
| H6 | 完整框架达到或超过 SOTA，且推理成本可接受 | 主实验 + 效率实验（第5、8章） |
| H7 | 语义先验与修正模块"主干无关、即插即用" | 跨主干实验（第9章） |
| H8 | 框架具有良好的跨数据集泛化性 | 跨数据集实验（第9章） |

**成败标准（提前写死，避免事后找补）**：
- ✅ 成功：三个数据集上全面超过 GeleNet（Sα 至少 +0.3%）；且至少与 IPDiff / SAM2-RS 打平；难例子集 Sα +1% 以上；消融 H2/H4 成立。
- ⚠️ 部分成功：整体打平但难例子集显著提升 + 成本/效率优势明显 → 论文转向"语义难例专精 + 低成本"叙事。
- ❌ 失败兜底：见第 12 章预案。

## 第 2 章 环境、预算与准备

### 2.1 硬件与软件
- GPU：**单卡 ≥12GB 显存即可**（GeleNet 原文用 Titan X 12GB 训练；RTX 3060/4070 Ti/A5000 均可）。
- 软件：PyTorch ≥2.0、CUDA 11.8+、Python 3.9+；代码基线 clone 自 [MathLee/GeleNet](https://github.com/MathLee/GeleNet)。
- API：DeepSeek 平台账号 + key；模型名 `deepseek-v4-flash-vision-exp`（现由 DeepSeek-V4.1-Flash 服务，等价 `deepseek-flash`）；OpenAI 兼容接口 `https://api.deepseek.com`。

### 2.2 预算（写进论文"成本分析"节）

| 项目 | 张数×调用 | token 估算 | 费用估算（非高峰） |
|------|-----------|-----------|------------------|
| 先验库（全数据集） | 7,000 × 1 | 输入 7.2M + 输出 2.1M | ≈ $2.5 |
| 诊断库（训练集） | ～4,000 × 1 | 输入 4.1M + 输出 1.2M | ≈ $1.4 |
| 在线推理（测试集） | ～3,000 × 1 | 同诊断量级 | ≈ $1.1 |
| 试点/重试/失败余量 | ～500 × 若干 | — | ≈ $2 |
| **合计（留足余量）** | | | **预算 $15，预期 $6～8** |

> 高峰时段价格 ×2，建议批量任务安排在周末（全程非高峰价）。充值 $15 足够跑完全部实验并留出重复实验余量。

## 第 3 章 数据集与划分

| 数据集 | 总量 | 训练/测试 | 特点 |
|--------|------|----------|------|
| ORSSD | 800 | 600/200 | 首个 ORSI-SOD 公开集 |
| EORSSD | 2,000 | 1,400/600 | 场景更复杂 |
| ORSI-4199 | 4,199 | 2,000/2,199 | 规模最大、最具挑战 |

- 训练协议（与四篇论文一致，保证公平对比）：
  - **ORSSD + EORSSD 联合训练**（2,000 张），在各自测试集上评测；
  - **ORSI-4199 单独训练**（2,000 张），在其测试集评测。
- 数据增强：随机旋转、水平翻转 + 旋转（沿用 GeleNet）。
- 输入尺寸：352×352（与 GeleNet/IPDiff/SAM2-RS 一致）。
- **随机种子**：主实验跑 **3 个种子**，报告 mean±std（新手常忽略这一点，审稿人会看）。
- **跨数据集泛化实验**（H8）：在 ORSSD 上训练、直接测 EORSSD/ORSI-4199 测试集（不微调）——证明先验与模块不是"背数据"。

## 第 6 章 各阶段详细设置

### 阶段0：基线复现 + API 试点（第 1～2 周）

**0a. GeleNet 复现**
- 直接跑官方代码，ORSSD/EORSSD/ORSI-4199 三个测试集，记录 Sα/Fβ/Eξ/MAE。
- **验收**：与论文报告值差距 ≤0.5% Sα，视为环境正常；否则检查预处理/评测代码。

**0b. DeepSeek API 试点（50 张，务必先试点再全量）**
- 从三个数据集各抽 ～17 张（含明显难例），用先验模板 + 诊断模板各调一次。
- **质检标准**：JSON 解析成功率 ≥95%；类别词落在固定词典内；人工抽 10 张判断"类别与方位描述是否合理"。
- 试点发现模板问题就改模板重试——**全量之前的所有修正是免费的**。

**0c. 固定类别词典**（写进提示词模板，防类别词漂移）
```
ship, airplane, vehicle, building, river, island, playground, road,
bridge, tree, storage tank, harbor, farmland, cloud shadow, none
```
模板要求 LLM 的 `salient_categories` 只能从该词典选择；"none" 对应无显著目标场景（ORSI-SOD 数据集中存在此类样本）。

### 阶段1：先验库 / 诊断库全量构建（第 2 周）

- **先验库**：7,000 张 × 先验模板（JSON Output + temperature=0 + detail:"low"）。断点续跑 + 失败重试 3 次 + 失败清单人工处理。产出 `prior_bank.json`。
- **诊断库**：先训练出阶段2的 M1 模型（见下），用 M1 对**训练集**（ORSSD+EORSSD 2,000 张；ORSI-4199 训练集 2,000 张）推理得 S⁰ → 渲染红色叠加图 → 调用诊断模板 → 产出 `diag_bank.json`。同时在训练集上用 GT 计算 A_miss/A_fp 监督标签（漏检区 = GT−S⁰>0.5 的像素；误检区 = S⁰−GT>0.5 的像素）。
- **注意**：先验库和诊断库**都要随代码开源**（可复现性的关键），两个 JSON 各 ～2～5 MB，不影响仓库体积。

### 阶段2：方案 A（SPIM）训练与消融（第 3～4 周）

**训练设置（沿用 GeleNet 的超参）**：Adam，初始 lr=1e-4（每 30 epoch ×0.1），共 45 epoch，batch=8，损失 L_BCE+L_IoU；SPIM 与主干一起端到端训练；文本编码器冻结。

**消融组（先验生成方）**：

| 变体 | SPIM 输入 | 目的 |
|------|-----------|------|
| Base | 无（= GeleNet 复现值） | 基线 |
| +CLIP-Txt | 固定模板文本 "A photo of a ship"（无 LLM） | 检验 H2（LLM 语义 > 静态文本） |
| +LLM-Cat | LLM 类别嵌入 only | 拆解类别贡献 |
| +LLM-Cat+App | 类别+外观 | 拆解外观贡献 |
| +LLM-All | 类别+外观+难例+粗方位（完整 SPIM） | 完整方案 A |

**结构微消融（若有时间）**：SPIM 注入 1 层 vs 4 层；交叉注意力 vs 简单拼接+1×1 卷积；文本编码器 CLIP vs BGE-m3。

**预期**：+LLM-All > +LLM-Cat+App > +LLM-Cat > +CLIP-Txt > Base，Sα 提升 0.3～1.5%。
**预案**：若 +CLIP-Txt ≈ +LLM-All → 说明增益来自"文本"而非"LLM 推理"，此时把 H2 调整为"文本先验有效"，并把创新重心压到方案 C；若全部无增益 → 检查语义嵌入与视觉特征的通道/尺度对齐，换注入位置（改在骨干浅层）或加通道 gating。

### 阶段3：方案 C（SEM-RM）训练与消融（第 5～6 周）

**训练设置**：冻结 M1；仅训练 SEM-RM（<2M 参数），lr=1e-4，30 epoch，损失 L_corr（S¹ 的 BCE+IoU + A_miss/A_fp 的逐像素 BCE 监督，权重 1:1:0.1:0.1）。

**消融组（修正方式）**：

| 变体 | 诊断来源 | 目的 |
|------|---------|------|
| M1（阶段2最优） | — | 方案 A 上限 |
| +Blind-Refine | 无诊断文本（去掉 FiLM 输入，纯 refine 模块） | 检验 H4 的一半：修正模块本身有用？ |
| +Fixed-Text-Refine | 固定通用诊断句（"检查漏检与误检"） | 检验诊断内容是否有意义 |
| +LLM-Diag-Offline | 离线诊断库（训练集缓存） | 完整方案 C |
| +LLM-Diag-Online | 推理时实时调用 | 在线模式上限 |
| IPDiff 式对照 | 把诊断替换为扩散式随机扰动迭代 | **直接对照 H4：语义引导 > 盲迭代** |

**轮数消融**：修正 1 轮 vs 2 轮（第二轮把 S¹ 再渲染问一次"是否仍有错误"）。
**预期**：+LLM-Diag-Online ≥ +LLM-Diag-Offline > +Fixed-Text > +Blind-Refine ≈ 或 > M1；1 轮与 2 轮差距 <0.1% Sα（若如此，论文采用 1 轮，省成本）。
**预案**：若 +Blind-Refine ≈ +LLM-Diag → 诊断文本没被有效利用，检查 e_diag 编码质量与 FiLM 结构（可改交叉注意力调制）；若全部修正变体 < M1 → 修正模块训练不稳（注意力图监督权重过大），调小权重或先不加监督项。

### 阶段4：主实验（第 7 周）

**对比方法列表（论文主表）**，分四代 + 新工作：

| 组别 | 方法（示例） |
|------|-------------|
| CNN 代 | MCCNet、ACCoNet、CorrNet、ERPNet |
| Transformer 代 | GeleNet、VST、ICON、MRBINet |
| 大模型/扩散代 | SAM2-RS、IPDiff |
| 文本融合新工作 | 2026 年文本-视觉融合方法（至少 1～2 个） |
| **本文** | **DS-SOD（离线模式）+ DS-SOD（在线模式）** |

- 每数据集一张主表：方法 × {Sα, Fβ_max, Fβ_mean, Eξ_max, Eξ_mean, MAE}；另出 PR/F 曲线图。
- 3 个种子取均值±标准差；显著性检验（可选：配对 t 检验 vs GeleNet）。

### 阶段5：附加实验（第 7～8 周）

1. **场景分组评测（H5，论文区分度所在）**：用先验库的 `challenges` 字段对测试集打标签（每图可取多个），分组统计：
   - 组别建议：低对比、阴影干扰、多目标、极大型目标、同谱异物（如船/海面）、无显著目标（"none"）。
   - 报告 DS-SOD vs GeleNet vs IPDiff 在各子集的 Sα/MAE；预期增益集中在难例组。
   - **实现提示**：先验库已给每张图打了 challenges 标签，测试集分组零成本。
2. **效率与成本实验（H6）**：参数量（PVT-v2-b2 约 25M + SPIM/SEM-RM <3M）、FLOPs、FPS（离线/在线）、每图 API 延迟、总 API 花费；画"API 调用次数 vs Sα"权衡曲线。
3. **跨主干实验（H7）**：把 SPIM+SAM-RM 移植到另一个开源基线（如 MCCNet 的 VGG 编码器-解码器，或 IPDiff 的去噪网络），证明即插即用。
4. **跨数据集泛化（H8）**：ORSSD 训练 → EORSSD/ORSI-4199 测试。
5. **定性可视化**：四类难例的成功/失败案例对比图 + LLM 思考过程（Thinking 模式输出）截图 → 支撑"可解释性"卖点。
6. **失败分析**：汇总 DS-SOD 仍失败的案例，用 LLM 归因（"失败集中在云雾遮挡/超小目标"）→ 写进论文 future work。

## 第 9 章 工程执行细节（照着做即可）

1. **批量脚本必须支持**：断点续跑（已完成清单按文件名记录）、失败重试 3 次、并发 20～50、0.2s 间隔、日志落盘。
2. **JSON 校验**：解析后校验字段与词典合法性；不合法的图进入人工队列（预期 <3%）。
3. **随机性控制**：temperature=0；全部中间产物（JSON、渲染图、嵌入）落盘；实验配置用 yaml 记录，确保可复现。
4. **评测脚本**：直接复用 GeleNet 仓库评测代码，保证指标口径与四篇论文一致。
5. **渲染图参数**：透明度做小网格 {0.3, 0.4, 0.5}，在试点 50 张上人工比较后固定。
6. **LLM 输出语言**：类别强制英文（词典约束），appearance/challenges 允许中文，编码器用 BGE-m3（CLIP 对比作为消融）。

## 第 10 章 风险与预案（每一类风险都有出口）

| 风险 | 概率 | 预案 |

## 第 11 章 与四篇论文的公平性声明（写进论文实验节）

1. LLM 仅接收图像，不接触任何 GT；
2. 先验库、诊断库、提示词模板全部开源；
