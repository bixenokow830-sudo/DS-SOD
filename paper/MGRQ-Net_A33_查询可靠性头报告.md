# MGRQ-Net A33｜查询可靠性头实验报告

## 1. 执行结论

A33已完成训练、干净提示评测和两档背景框压力测试，工程完整性验收通过，但研究门未通过。模型在A32基础结构中加入I25双分支可靠性头，预测目标存在概率`p_obj`和掩码质量`p_iou`，查询可靠性定义为`r=p_obj×p_iou`，最终显著图使用`max(sigmoid(mask_i)×r_i)`。

可靠性头本身没有塌缩，并能区分匹配与未匹配查询：干净dev上正查询平均可靠性为0.5248、负查询为0.1084、ROC-AUC为0.8488。但是可靠性直接乘到掩码概率后过度压低有效查询，A33干净提示宏平均Sα为0.8286，比A32的0.8348下降0.0063，超过预设的0.005最大容忍值；三个数据集的Sα均下降、MAE均上升。

此外，当前随机背景框压力测试没有形成有效破坏：A32加入1个或3个框后Sα反而分别提高0.0002和0.0004。因此不能用这组结果宣称A33抗噪性提高。阶段结论为：

```text

```

## 2. 方法配置

| 项目 | A32 | A33 |
|---|---|---|
| 查询输入 | RoI＋框＋置信度＋CLIP文本 | 相同 |
| 查询类型 | 关闭 | 关闭 |
| 发现查询 | 0 | 0 |
| 可靠性头 | 无 | `p_obj`与`p_iou`双分支 |
| 可靠性监督 | 无 | 匹配查询为正，未匹配/重复查询为负 |
| 质量目标 | 无 | 当前二值掩码与匹配GT组件的IoU |
| 显著图 | `max(sigmoid(mask_i))` | `max(sigmoid(mask_i)×p_obj×p_iou)` |
| 训练初始化 | seed 42从头训练 | seed 42从头训练 |

可靠性损失为目标存在Focal Loss与质量Smooth L1之和。总损失包含组件匹配损失、可靠性加权整图并集BCE+Dice和可靠性损失，三项权重均为1。

| EORSSD | 0.8095 | 0.8038 | −0.0058 | 0.0169 | 0.0181 | +0.0013 |

## 5. 可靠性诊断

干净提示下共有1,647个有效查询，其中672个经匈牙利匹配为正查询、975个为未匹配或重复负查询。

| 指标 | 结果 |
|---|---:|
| 可靠性均值 | 0.2783 |
| 标准差 | 0.3861 |
| 最小值 / 最大值 | 0.0068 / 0.9902 |
| 正查询均值 | **0.5248** |
| 负查询均值 | **0.1084** |
| 正负均值差 | 0.4164 |
| ROC-AUC | **0.8488** |
| `p_obj`均值 | 0.5780 |
| `p_iou`均值 | 0.3299 |

可靠性范围和标准差说明输出没有坍缩为全0或全1；AUC和正负均值差说明查询排序具有信息。但是正查询平均权重只有0.5248，直接与掩码概率相乘会把许多正确查询的峰值压到约0.5附近。这解释了“可靠性可分，但最终显著图更差”的现象。

## 6. 背景框压力测试

压力框按seed 42确定性生成，框宽高为归一化坐标100–350，并使用GT仅在离线诊断阶段筛选框内前景占比不高于1%的位置。加入框使用背景占位文本、置信度0，不参与任何模型训练。

| 方法 | 干净Sα | +1背景框Sα | 相对干净变化 | +3背景框Sα | 相对干净变化 |
|---|---:|---:|---:|---:|---:|
| A32 | 0.8348 | 0.8350 | **+0.0002** | 0.8353 | **+0.0004** |
| A33 | 0.8286 | 0.8295 | **+0.0010** | 0.8304 | **+0.0018** |

两种方法都没有因所谓污染而下降。其原因是查询解码器通过全图交叉注意力生成掩码，低前景占比框并不保证新增查询只预测背景；额外查询的最大值并集反而可能补到原先漏检的前景。因此本次压力输入不满足“先让A32发生可测下降”的前提，`A33下降更小`不可判定，不能把数值上更大的提升解释为抗噪优势。

污染条件下A33可靠性仍保持一定可分性，但逐渐减弱：

| 条件 | 正查询均值 | 负查询均值 | ROC-AUC |
|---|---:|---:|---:|
| 干净 | 0.5248 | 0.1084 | 0.8488 |
| +1框 | 0.5178 | 0.1285 | 0.8287 |
| +3框 | 0.4906 | 0.1401 | 0.7957 |

新增背景查询使负查询均值上升、AUC下降，说明当前可靠性头对分布外污染仍不够稳健。

## 7. 失败原因判断

本次失败不是可靠性头完全学不会，而是可靠性使用方式与压力协议存在两个具体问题：

1. **乘法门控过强。** `p_obj×p_iou`对两个小于1的概率进行二次衰减，再直接缩放掩码概率。即使正查询排序正确，平均0.5248的权重仍会明显降低前景响应和校准。
2. **训练目标与最终幅值耦合。** `p_iou`被训练为真实质量回归值，而不是“是否应保留”的门控概率。中等质量但必要的查询被按IoU幅度压低，可能损伤前景完整性。
3. **污染样本过弱。** GT约束的空背景框、置信度0和明确背景文本共同提供了容易识别的低风险输入；全图查询解码又允许它们补回前景，因此没有形成有效的错误显著候选。
4. **从头联合训练混合了优化差异。** A33与A32均从头训练，但可靠性损失改变了基础解码器梯度；当前差值既包含推理门控，也包含联合优化影响。

## 8. A33-R1具体修复方案

在进入A34前建议执行范围受控的A33-R1：

1. **从A32最终权重初始化并先冻结基础网络。** 只训练可靠性头1个epoch，避免重新优化基础解码器造成混杂；随后最多用`1e-5`联合微调1个epoch。
2. **把乘法幅值门改为残差软门。** 使用
   `g_i = λ + (1−λ)r_i`，先固定`λ=0.5`，最终显著图为`max(sigmoid(mask_i)×g_i)`。这样低可靠性查询仍被抑制，但正确查询不会被压到原幅值的一半以下。
3. **质量分支只用于排序或校准。** 对比`p_obj`单门控与`p_obj×p_iou`；若质量乘积继续损害干净性能，主模型只使用`p_obj`，`p_iou`保留为辅助诊断输出。
4. **构造真正困难的污染。** 背景框仍选低GT占比位置，但赋予0.8–0.95高置信度，并配入从其他图像错配来的显著短语；先要求A32在+3污染下Sα至少下降0.002，再比较A33-R1的下降幅度。
5. **门禁保持不变。** 干净Sα相对A32下降不得超过0.005；正负AUC需高于0.6；有效污染下A33-R1下降必须小于A32。

## 9. 结论边界

A33证明了查询特征中存在可学习的可靠性信号，但没有证明当前可靠性加权并集能提高最终遥感显著性检测性能，也没有证明其对错误提示更稳健。因此论文现阶段可以保留“可靠性可预测”的诊断证据，不能把当前A33作为最终方法或正向消融结果。

在A33-R1修复干净性能与压力协议之前，不进入A34，否则发现查询实验会建立在一个已知退化的底座上，难以解释增益来源。
