# MGRQ-Net A34-R2 选择式发现门控实验报告

## 1. 阶段结论

A34-R2 已完成门控训练、训练内阈值校准和 400 张严格内部验证。工程状态为 **PASSED**，研究验收门为 **FAILED**，DeepSeek API 调用为 0。

A34-R2 修复了 A34-R1 的幅值塌缩和评测口径问题：删除 30% 正确候选时，统一口径的组件召回率由 0.403250 提升至 0.444609，增益为 0.041359；完全移除 MLLM 候选时，发现查询召回率恢复至 A34 的 0.353028。干净集 S 相对 A33-R1 仅下降 0.001514，满足预设限制。

研究门失败的原因是选择器没有学会“何时启用”。训练内校准集只有 3 个有用发现查询正样本，最终阈值退化为最低候选值 0.05，并在每张图上固定选择 1 个发现查询。该策略保留了补漏能力，但干净集重复选择率仍达到 50.75%，Macro MAE 增加 0.001548，超过允许的 0.001。

- 随机种子：42。
- 严格训练集：2928 张。

- 训练内校准子集：293 张，占 10%。

- 发现掩码启用后保留原始幅值，新颖性只使用 `[0.5, 1.0]` 线性缩放。
- 无 MLLM 候选时强制启用全部发现查询。

## 6. 失败原因定位

### 6.1 有用发现查询属于极少数事件

2635 张门控训练图中只累计得到 49 个有用正查询。293 张校准图中仅有 3 个正查询，而负查询超过一千个。此时门控阈值估计高度不稳定。

### 6.2 校准结果表明门控没有可用的判别精度

训练内校准选择结果为：

- 阈值：0.05。
- 真阳性：3。
- 假阳性：290。
- 召回率：1.0。
- 精确率：0.010239。

由于没有任何阈值能达到预设的 75% 精确率，校准器退回 F0.5 最优解；该解实际上等价于“每张图固定选择分数最高的一个查询”。因此，当前门控分数没有承担有效的开关作用。

### 6.3 Top-1 限制降低数量，但没有解决重复对象选择

A34 的问题是每张图存在多个重复发现查询；A34-R2 将其压缩为每图一个，却没有判断这个唯一查询是否仍在重复 MLLM 已覆盖的对象。干净集 400 个被选查询中有 203 个属于重复选择，重复率为 50.75%。

### 6.4 压力条件的收益证明模块不能直接删除

尽管选择器失效，A34-R2 在删除 30% 候选时仍同时提高 S、降低 MAE，并补回 28 个组件。这表明发现查询值得保留，但应由图像级“是否缺失”路由器控制，而不是在所有图像上固定启用。

## 7. 建议执行 A34-R3：反事实缺失增强与两级路由

### 7.1 从查询级开关改为两级决策

第一层判断当前 MLLM 分支是否可能漏检，第二层只在需要时选择具体发现查询：

```text
p_missing = ImageMissingRouter(MLLM汇总特征)
if p_missing >= τ_image:
    q* = argmax QueryUtility(discovery, MLLM)
    output = max(M_mllm, M_discovery[q*])
else:
    output = M_mllm
```

图像级输入建议包括：

- MLLM 候选数量、平均置信度与最大置信度。
- A33-R1 查询可靠性均值、最小值和方差。
- MLLM 联合掩码面积与空间熵。
- 发现查询相对 MLLM 联合掩码的最大新颖性。

### 7.2 用反事实候选删除解决正样本稀缺

当前训练只使用完整候选，导致有用发现事件极少。对每张严格训练图生成配对输入：

- 原始候选：标签为是否真实存在可恢复漏检。
- 随机删除 30% 候选。
- 随机删除 60% 候选。
- 删除全部候选。

删除操作不需要 GT 选择候选，只随机删除模型输入；GT 仅用于生成监督标签，不进入模型。这样可显著增加“MLLM 缺失但发现查询能够补回”的正样本，同时避免推理泄漏。

### 7.3 使用图像级平衡采样

- 对 `missing=1` 图像进行过采样，使每个训练批次正负比例接近 1:3。
- 图像路由器使用 focal loss 或 class-balanced BCE。
- 查询排序使用正查询与重复查询之间的 margin ranking loss。
- 发现查询本体、A32 和 A33-R1 全部冻结，只训练路由器。

### 7.4 校准目标改为效用约束

不再用极低基率下不稳定的查询 F0.5 选择阈值。训练内校准集应选择满足下列约束的图像阈值：

- 干净配对上的重复启用率低于 15%。
- 删除候选配对上的可恢复漏检召回率尽可能高。
- 若没有阈值同时满足约束，则阶段直接失败，不回退到“每图必选”。

### 7.5 A34-R3 验收条件

- 干净集发现分支启用率低于 20%。
- 干净集重复选择率低于 20%。
- 干净集 Macro S 相对 A33-R1 下降不超过 0.002。
- 干净集 Macro MAE 相对 A33-R1 上升不超过 0.001。
- 删除 30% 候选时组件召回增益不低于 0.02。
- 无 MLLM 候选时强制启用发现查询，组件召回不低于 0.30。
- 阈值仅由严格训练内校准集确定；dev 不参与调参。

## 8. 阶段决策

A34-R2 已同时证明两点：发现查询具有稳定补漏价值，但查询级稀有事件分类不足以决定是否启用。推荐下一步执行：

**A34-R3：使用随机候选删除构造反事实正样本，训练图像级缺失路由器；只有路由器判定可能漏检时，才启用一个发现查询。**
