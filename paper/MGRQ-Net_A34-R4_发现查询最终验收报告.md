# MGRQ-Net A34-R4 发现查询最终验收报告

## 1. 最终结论

A34-R4 已完成训练内规则校准和 400 张严格内部验证，工程状态与研究验收门均为 **PASSED**。本阶段没有训练任何神经网络参数，也没有调用 DeepSeek API。

A34-R4 在冻结 A34-R3 的基础上，仅增加新颖性重排与 MLLM 重叠否决规则，将干净集条件重复率从 54.90% 降至 11.76%，同时保留删除 30% 正确候选时 0.028065 的组件召回增益。干净集 Macro S 相对 A33-R1 提高 0.000560，Macro MAE 仅增加 0.000110。

至此，A34 系列的核心目标已经实现：发现查询只在 MLLM 存在漏检风险时启用，优先选择与现有 MLLM 掩码不重叠的视觉目标，并在完全缺少 MLLM 候选时提供纯视觉兜底。

## 2. 最终结构

A34-R4 的推理流程为：

```text
DeepSeek候选 + 本地文本嵌入
          ↓
冻结A32查询构建与掩码解码
          ↓
冻结A33-R1 MLLM可靠性门控 ─────→ M_mllm
          ↓
冻结A34视觉发现查询
          ↓
A34-R3图像级缺失路由器
          ↓ 仅在可能漏检时
新颖性重排 + MLLM重叠否决
          ↓
选择一个发现查询 M_discovery
          ↓
max(M_mllm, M_discovery)
```

无 MLLM 候选时，系统跳过重叠否决并强制启用全部发现查询，保持视觉兜底能力。

## 3. 固定配置

- 随机种子：42。
- 严格训练集：2928 张；内部验证集：400 张。
- A34-R3 图像路由阈值：0.35。
- A34-R4 新颖性权重：0.25。
- 发现查询与 MLLM 联合掩码的软重叠上限：0.50。
- 每张有 MLLM 候选的图最多启用 1 个发现查询。
- 无 MLLM 候选时强制启用全部 5 个发现查询。
- A32、A33-R1、A34 发现查询及 A34-R3 路由器全部冻结。
- A34-R4 可训练参数：0。
- 规则校准样本：293 张训练内图像形成的 879 个输入。
- 400 张 dev 未参与规则选择。
- DeepSeek API 调用：0。
- 官方测试集：未使用。

## 4. 训练内校准结果

校准集成功找到满足约束的规则：

- 干净输入发现选择率：14.68%。
- 干净输入条件重复率：6.98%。
- 反事实缺失恢复率：83.93%。
- 恢复成功：47/56。

这表明重叠上限 0.50 能在训练内数据上有效排除重复查询，同时保留大部分候选缺失补漏能力。

## 10. 后续实验建议

A34-R4 已完成发现查询模块的内部验证，不建议继续进行 A34-R5。后续应：

1. 将 A34-R4 固定为 MGRQ-Net 的发现查询版本。
2. 冻结所有 A34-R4 参数和规则，记录检查点哈希。
3. 进入下一计划阶段，开展多随机种子、消融实验或与主流方法的统一测试集比较。
4. 在论文中将发现查询定位为“MLLM 提示缺失时的条件视觉兜底”，而不是始终参与的第二主分支。
5. 明确 DeepSeek 只用于离线生成候选描述；A34-R4 推理阶段不调用 API。
