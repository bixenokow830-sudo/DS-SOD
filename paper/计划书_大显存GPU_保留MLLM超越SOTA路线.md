# 计划书：使用大显存 GPU、保留 MLLM，冲击并超越全监督 SOTA

> 适用前提：现有 8GB 路线已确认范式天花板 0.9072（三集平均）< GeleNet 0.9236 < IPDiff 0.9310，
> 且该天花板**与算力无关**（受"冻结主干 + 4.22M 解码器"定义）。本计划书给出打破天花板的路径。
> 制定日期：2026 ｜ 状态：待决策

---

## 一、目标与成功判据（先定"什么算成功"）

| 层级 | 判据 | 说明 |
|------|------|------|
| **最低目标** | 三测试集平均 Sα ≥ **0.92**，且在 ≥2 个数据集上 ≥ GeleNet（0.9469/0.9376/0.8862） | 进入"与全监督同级"区间，可写"competitive with fully supervised" |
| **理想目标** | 三集平均 Sα ≥ **0.94**，逼近/超过 IPDiff（0.9557/0.9461/0.8907） | 可写"surpasses SOTA"，需同时报告参数量与训练成本优势 |
| **保底交付** | 若只到 0.90～0.92 | 论文改写为"轻量适配的高效方案"，与全监督比**参数/成本**而非绝对精度 |
| **明确失败** | S1/S2 相对现状（0.8665）增益 < +1 点 | 判定该范式封顶，回到"机制与边界"定位，本计划结论写入 future work |

**核心约束（保留 MLLM）**：MLLM 始终是"什么显著"的语义来源。计划中**不替换 MLLM**，只改变
解码/特征侧，并在 S3 可选地微调一个开源 VLM 以提升提示质量。

---

## 二、现状诊断：天花板从哪来

| 事实（已实测） | 数值 | 推论 |
|---|---|---|
| GT 完美框 + 冻结主干 + 4.22M 解码器 | 0.9072（三集平均） | **提示侧已到极限**；差距 100% 在解码侧 |
| SAM2 base+ → large（2.8 倍参数，仍冻结） | +0.2 点（零增益） | 单纯"更大的冻结模型"无效 |
| 提示侧残余空间 | 约 3.7 点（ORSSD），其中漏检 oracle +1.57、范围 +0.80 | 提示侧还能挤，但即便挤满也过不去 |
| 可训练参数 | 4.22M（GeleNet 25.45M、IPDiff 82.6M） | **我们的可训练容量只有对手的 1/6～1/20** |

**结论：必须让"特征本身"适配遥感显著域**——即训练 image encoder 的轻量适配器（这正是我们
唯一还没试过的方向）。

---

## 三、技术路线（三阶段，逐级 go/no-go）

### S1｜轻量主干适配（**现有 8GB 即可试**，2～3 天）

**做什么**
- 在 SAM2.1 Hiera base+（80.85M，冻结主干权重）的 **最后 1～2 个 stage** 插入 bottleneck adapter
  （`down(→64) → GELU → up(→C)`，残差连接）；或等效 LoRA（rank 8～16）加于 QKV/Proj。
- 与 mask decoder（4.22M）**联合训练**，其余全部冻结。
- 可训练参数：约 **10～12M**（仍是 GeNeNet 的 40% 量级）。

**为什么可能有效**
- 天花板来自"冻结特征不是显著特征"；adapter 直接改变最后两 stage 的特征表达，正是针对该病因。

**显存与实现要点**
- 需对最后 1～2 个 stage 反传 → 激活内存上升。措施：对这些 stage 开 **gradient checkpointing**、
  bf16 混合精度、batch=1。估计峰值 **6～8GB**，8GB 卡可行但紧；若 OOM 则只适配最后 1 个 stage。
- 训练协议沿用现状：4000 张原图 × 3～5 epoch。
- **一个重要修正**：当前训练用"GT 框 + 抖动"，而推理用"MLLM 框 + PRISM"——**存在分布错配**。
  S1 应同时试两种提示源训练，并以"推理时真实提示分布"为准（预计这一项本身就能带来正收益）。

**成功判据（dev 50，不动测试集）**：dev Sα 从 0.874 → **≥ 0.90**。

**失败即停**：若 +1 点以内无增益 → 直接判定范式封顶，不必进入 S2。

### S2｜全主干适配 + 高分辨率（**需 24GB 云卡**，1～2 周）

**做什么**
- adapter 覆盖全部 4 个 stage；可选**解冻最后 1 个 stage 全参**。可训练 **20～30M**。
- 输入分辨率 1024 → **1536**（SAM2 位置编码可插值）——遥感的车/船/储罐等小目标定位质量
  主要由分辨率决定，这是 8GB 卡做不到的部分。
- 训练：10～20 epoch、cosine LR、EMA、多尺度（0.8～1.2×）；损失 BCE + IoU + 可选边界损失。

**成功判据（测试集只评一次）**：三集平均 **≥ 0.92**，且 ≥2 个数据集 ≥ GeleNet。

**预期（估计，非实测）**：0.91～0.94。**不保证**，因为 SAM2-RS（同类路线）的具体数值我们无法核实。

### S3｜微调开源 VLM 提升提示质量（**需 24～48GB**，1～2 周，可选）

**做什么**
- 选 Qwen2.5-VL-7B 或 InternVL-2.5-8B，LoRA（r=16～32）微调；
- 监督数据**自动生成**：4000 张训练图 + GT 连通域框 → "(图 → 显著类别 + 框)" SFT 对
  （类别可由 ORSI-4199 文件名与现有提示库提取，**零人工标注**）；
- **加入难例挖掘**：把"框在无显著区域"的样本作为 hard negative，直接针对我们实测的
  32.1% "选错目标"错误。

**成功判据**：dev 上提示框严格匹配率 **47.2% → ≥65%**；下游 Sα 再 +1～3 点。

**⚠️ 定位影响**：S3 使用了训练集的 GT 反推监督，"提示侧零标注"的说法不再成立，论文需改写为
"**轻量监督 + 语言可解释**"。若不接受该定位变化，则不做 S3。

## 四、与同类工作的差异化（必须守住）

| 对比对象 | 他们的做法 | 我们的差异 |
|---|---|---|
| SAM2-RS (TGRS 2026) | 冻结 SAM2 + **盲学习提示向量**（无语义）+ 频域适配 | 我们保留 **MLLM 语言提示 + PRISM 提示可靠性修复**，输出可读理由；提示侧不使用标注 |
| Saliency-R1 | SFT + RL 训练 MLLM 输出参照表达式 | 我们先用**零训练提示 + 结构化修复**；微调仅作为可选增强 |
| GeleNet / IPDiff | 端到端全监督、25～82M 全参训练 | 我们报告**可训练参数少 6～20 倍**、训练时间 46 分钟级、API 成本 $5.59 |

**关键**：即使走到 S2，我们的故事仍是"**语言驱动 + 提示修复 + 轻量适配**"，而不是"又一个
SAM 适配器"。PRISM（错误解剖 → 类别一致性过滤 → 掩码自收紧 → 超大框守卫）是我们独创且已实测
+2.76 点的模块，应始终保留在流水线中。

## 五、评测协议与公平性（投稿红线）

1. **同一训练集**：与 GeleNet/IPDiff 用同样的训练划分（4000 张原图），不额外加数据；
2. **模型选择纪律**：S1/S2 的调参只用 **dev 50 + 训练集内部子集**；**测试集在最终配置确定后
   只评一次**并如实报告（此前 8GB 阶段为开发便利多次评测测试集，转新路线后必须收紧）；
3. **报告三件成本**：可训练参数、训练 GPU 小时、API 花费；
4. **空标注图口径**：报告指标时说明 EORSSD 40 张 / ORSSD 4 张 GT 前景 <0.1% 的图；
5. **MLLM 污染风险**：若保留 API 模型，需声明无法排除预训练见过公开基准；若 S3 改用开源 VLM，
   该风险显著降低（权重可控、可给出训练数据构成）。

## 七、失败预案（每阶段都有出口）

| 情形 | 处置 |
|---|---|
| S1 无增益（<+1 点） | 停止投入，确认范式封顶；本计划结果写为 future work；论文维持 v0.7"机制与边界"定位 |
| S2 到 0.90～0.92 但仍低于 GeleNet | 论文定位改为"轻量适配的高效方案"：强调参数少 6～20 倍、训练 46 分钟 vs 44 epoch，做**精度-成本 Pareto**对比 |
| S2 ≥ GeleNet 但 < IPDiff | 写"与 2023 SOTA 同级、逼近 2026 SOTA"，并突出语言可解释性与零提示标注 |
| S3 提示质量不升 | 放弃 VLM 微调，保留 API 模型 + PRISM（现有方案） |
| 云环境配置受阻 | 预先在本地打包环境（CUDA 版本、SAM2 仓库、依赖清单、数据清单），用脚本一键部署 |
