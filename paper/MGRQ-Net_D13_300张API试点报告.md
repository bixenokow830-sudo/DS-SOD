# MGRQ-Net D13：300张 DeepSeek API 试点报告

## 1. 结论

D13 验收通过，状态为 `PASSED_SINGLE_IMAGE_TEMPLATE_FROZEN`。

- 最终解析成功率为 **300/300（100%）**，超过不低于 99% 的决策门槛。
- 相比旧 DS-SOD 提示库，新提示的 GT 组件召回率由 **51.90%** 提升到 **74.66%**，小目标组件召回率由 **25.19%** 提升到 **52.26%**。
- 小目标切片触发规则未满足，因此不执行 2×2 切片 API 对照，冻结 `mgrq_prompt_v1_2026-10-19` **单整图提示模板**。
- 新提示明显提高覆盖率，但框并集像素精确率由 31.20% 降至 25.40%，严重失配候选比例由 27.81% 升至 34.92%。这说明后续模型不能直接信任 MLLM 框，必须保留可靠性校准、负查询抑制和发现查询。

本结论只使用训练/内部验证划分的 GT 作诊断，未使用官方测试集 GT 选择模板或规则。

## 4. 定量定义

- 候选框严格匹配：候选框与任一 GT 连通组件外接框的 IoU 不低于 0.5。
- GT 组件召回：被任一候选框以 IoU 不低于 0.5 匹配的 GT 连通组件比例。
- 小目标组件：组件像素面积不超过整幅图像面积的 1%。
- 严重失配候选：候选框与所有 GT 组件外接框的最佳 IoU 小于 0.1。
- 像素召回率/精确率：将全部候选框栅格化为框并集后，与二值 GT 逐像素比较。
- 旧提示库中的框按其原始 `[x,y,w,h]` 语义转换；新提示框为 `[x1,y1,x2,y2]`。

这些指标评价的是离线提示覆盖质量，不等同于最终分割指标，也不能替代 S-measure、F-measure、E-measure 和 MAE 实验。

## 5. 与旧提示库对照

| 指标 | 新提示 | 旧提示 | 差值 |
|---|---:|---:|---:|
| 平均候选数/图 | 2.94 | 2.07 | +0.87 |
| 空候选图像 | 2/300 | 2/300 | 0 |
| 候选框严格匹配率 | 51.70% | 48.07% | **+3.63 pp** |
| GT 组件召回率 | 74.66% | 51.90% | **+22.76 pp** |
| 小目标组件召回率 | 52.26% | 25.19% | **+27.07 pp** |
| 框并集像素召回率 | 99.11% | 87.14% | **+11.98 pp** |
| 框并集像素精确率 | 25.40% | 31.20% | **-5.80 pp** |
| 严重失配候选比例 | 34.92% | 27.81% | **+7.11 pp（较差）** |

新提示的主要收益是“少漏目标”，代价是候选更多、覆盖框更宽、假阳性区域更多。这符合 MGRQ-Net 的设计前提：MLLM 负责提供高召回语义先验，监督分割网络负责校准、拒绝和恢复，而不是把 MLLM 框直接当最终掩码。

## 6. 分数据集诊断

| 数据集 | 新/旧组件召回 | 新/旧小目标召回 | 新/旧像素精确率 |
|---|---:|---:|---:|
| ORSSD | 86.21% / 70.11% | 72.97% / 43.24% | 21.38% / 27.02% |
| EORSSD | 74.19% / 41.29% | 65.81% / 28.21% | 18.44% / 20.18% |
| ORSI-4199 | 71.89% / 52.07% | 31.25% / 16.07% | 30.71% / 38.73% |

ORSI-4199 的小目标召回仍只有 31.25%，是后续 D15 与模型消融需要重点观察的风险项。不过它相对旧库接近翻倍，且总体小目标召回已达到 52.26%，所以本阶段不值得用约 5 倍调用量引入固定 2×2 切片。优先让发现查询补漏，并用可靠性头抑制宽框和误候选。

## 8. 决策门与冻结项

| 决策项 | 规则 | 结果 |
|---|---|---|
| 最终解析率 | ≥99% | 100%，通过 |
| 相对旧库质量 | 三项核心覆盖指标不得低于旧库超过 5 pp | 三项均提升，通过 |
| 2×2 切片触发 | 新小目标召回 <50%，或比旧库低 >5 pp | 52.26%，且高 27.07 pp，不触发 |
| 模板选择 | 单整图或整图+切片二选一 | 冻结单整图 |

冻结项如下：

- 提示模板：`mgrq_prompt_v1_2026-10-19`
- 输出协议：`mgrq_semantic_queries_v1`
- 坐标：整数 `[x1,y1,x2,y2]`，范围 `[0,1000]`
- 请求模型别名：`deepseek-flash`
- 推理方式：单整图、关闭思考模式
- 缓存：原始响应与解析结果分离，绑定图像 SHA256、清单哈希和请求签名

D14 可以在此冻结配置上生成 3600 张开发训练图和 400 张内部验证图的完整提示缓存，不覆盖 D13 原始响应。
