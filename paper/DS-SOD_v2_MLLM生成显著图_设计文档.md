# DS-SOD v2 设计文档：AI 生成提示词，DS 多模态大模型直接生成最终显著图

> 版本：v2.0 ｜ 取代：《DS-SOD完整框架详解_方案A+C.md》（v1，架构已废）、《DeepSeek大模型集成ORSI-SOD创新方案报告.md》（选题论证保留，路线更新）
> 一句话：**AI 链式生成提示词 → DS 多模态大模型输出"带坐标的结构化掩码" → 本地确定性渲染器画成最终显著图。CNN 不再生成显著图。**

---

## 第 0 章 思路调整：一句话 + 一张图 + 分工反转

### 0.1 一句话

**旧（v1）**：CNN 生成显著图，DeepSeek 只出文字先验（"LLM 给语义、网络定像素"）。

**新（v2）**：DeepSeek 多模态大模型**直接决定显著图的每一块区域**——AI 先生成提示词，DS 大模型据提示词输出多边形/框/点的坐标 JSON，本地渲染器只是"画笔"，把大模型画的内容忠实呈现（"LLM 定区域、渲染器定像素"）。

### 0.2 总框架图

```
                        ┌───────────────────────────────────────────┐
                        │  阶段1：AI 链式生成提示词（在线推理主流程）    │
                        │                                            │
  遥感图 I ──────────────► DeepSeek 多模态大模型                      │
     │                    │  Pass1 PromptGen：看图 → 输出"显著性命题"  │
     │                    │    {类别, 显著原因, 大致位置, 难例标签}     │
     │                    │        │（AI 生成的提示词）               │
     │                    │        ▼                                 │
     │                    │  Pass2 MaskGen：图 + 提示词 → 掩码 JSON    │
     │                    │    {多边形顶点 / 框 / 点 + 置信度，归一化坐标}│
     │                    └──────────────┬──────────────────────────┘
     │                                   ▼
     │                         阶段2：掩码渲染器（本地、确定性、无学习参数）
     │                          多边形扫描线填充 / 框 / 高斯点 → 显著图 S
     │                                   │
     │        ┌──────────────────────────┘
     │        ▼
     │  阶段3：MLLM 自修正闭环（可选，1～2 轮）
     │  原图 + S 红色叠加渲染图 ──► DeepSeek ──► 修正 JSON{add/remove/refine}
     │        │                                   ▼
     │        └────────────────────────────── 重新渲染 → S¹
     ▼
  最终显著图（全部区域由 DS 多模态大模型决定）
```

### 0.3 分工反转对照（写进论文的核心叙事）

| 维度 | v1（A+C 方案） | **v2（本方案）** |
|------|---------------|-----------------|
| 谁生成显著图 | 训练好的 CNN（GeleNet） | **DS 多模态大模型** |
| LLM 的角色 | 文字先验 / 诊断裁判 | **掩码生成者 + 提示词生成者 + 自我裁判** |
| 像素怎么定 | 网络卷积输出 | LLM 输出几何坐标 → 确定性栅格化 |
| 训练 | 需要（44 epoch × 3 数据集） | **零训练（主流程）**，可选少量标量校准 |
| 渲染器 | 无 | 多边形填充（无学习参数，"画笔"不是"画家"） |

## 第 1 章 为什么这样调：动机与技术可行性前提

### 1.1 动机（论文引言直接可用）

1. **v1 的尴尬**：SPIM/SEM-RM 本质是"LLM 给 CNN 打辅助"，审稿人一句"把 LLM 换成随机文本增益还剩多少"就能动摇整个方法；且 2026 年"文本融合 ORSI-SOD"已不新。
2. **v2 的差异化**：把 ORSI-SOD 从"视觉感知任务"重构为"**语言驱动的生成式检测任务**"——显著图由多模态大模型**直接生成**，这是四篇论文（MCCNet/GeleNet/IPDiff/SAM2-RS）以及 v1 都没做过的事。
3. **零训练卖点**：v2 主流程不需要任何 GPU 训练、不需要 GT。三数据集直接零样本评测，实验周期从 8 周压缩到 2～3 周，成本从"训练电费 + 几美元 API"变成"纯 API 几美元"。

### 1.2 技术可行性前提（先对齐事实，避免方案落空）

- DeepSeek API（`api.deepseek.com`）是"**图进 → 文字出**"的视觉理解接口，**没有图像生成端点**。因此"大模型生成显著图"的实现方式是：**大模型输出显著区域的几何表示（多边形/框/点坐标，即"掩码即文本"），由本地确定性渲染器画成图像**。
- 渲染器必须满足两条铁律，才能让"显著图由大模型生成"这个论断站得住：
  1. **零学习参数**：纯几何填充（扫描线算法），没有任何神经网络；
  2. **零视觉输入**：渲染器只读坐标 JSON，不看原图像素——显著图的全部内容都来自大模型的输出。
- 论文里的准确措辞：*"The final saliency map is generated by the DeepSeek multimodal model in the form of a structured geometric mask, which is rasterized by a deterministic, parameter-free renderer."*

### 1.3 对 v1 资产的处置

| v1 资产 | v2 处置 |
|---------|---------|
| GeleNet（PVT-v2 主干） | **降级为对比基线**（表1 的 Transformer 代成员），代码保留 |
| SPIM / SEM-RM | 降级为消融对照（"CNN+LLM 先验"vs"LLM 直接生成"），不再维护 |
| prior_bank.json / embed_cache | 存档；challenge_tags 字段在 v2 场景分组评测中复用 |
| 评测脚本 eval/metrics.py | 原样复用（指标口径不变） |
| 数据集 / 指标 / 对比方法清单 | 全部沿用 |

## 第 2 章 阶段1：AI 链式生成提示词（PromptGen → MaskGen）

**核心设计**：不让大模型"一步到位"直接吐坐标（幻觉重灾区），而是拆成两段式链：

- **Pass 1（PromptGen，提示词生成）**：看图 → 输出**自然语言显著性命题**（哪些目标显著、为什么、大致在哪、难例类型）。这就是"AI 生成的提示词"。
- **Pass 2（MaskGen，掩码生成）**：把原图 + Pass 1 的提示词一起喂给模型 → 输出**带坐标的结构化掩码 JSON**。
- （可选 Pass 2.5 Zoom-in：对 Pass 2 给出的每个目标框裁剪放大后再要一次局部多边形，大幅提升边界精度。）

### 2.1 Pass 1 提示词模板（PromptGen）

```
你是一名光学遥感图像显著性分析专家。请观察这张遥感图像，
先思考"哪些目标最吸引人类注意力、为什么"，再严格按 JSON 输出
（不要输出任何 JSON 以外的文字）：
{
  "reasoning": "一句英文思考过程，说明显著性与理由",
  "salient_instances": [
    {"category": "ship", "reason": "与深色海面形成强对比", "location_hint": "画面中部偏左"}
  ],
  "challenge_tags": ["similar_spectrum"]
}
规则：
- category 只能从词典选择：ship, airplane, vehicle, building, river, island,
  playground, road, bridge, tree, storage tank, harbor, farmland, cloud shadow, none
- salient_instances 按显著程度降序，最多 5 个；无显著目标时 category 为 "none" 且列表为空
- location_hint 用自然语言描述方位，禁止输出坐标
- challenge_tags 从词典选择：low_contrast, shadow, multiple_objects, large_object,
  similar_spectrum, small_object, clutter, none
```

### 2.2 Pass 2 提示词模板（MaskGen）

```
这是一张光学遥感图像，以下是先前分析得到的显著性提示词：
[此处粘贴 Pass 1 的完整 JSON]

请根据提示词，为每个显著目标给出精确的几何掩码，严格按 JSON 输出：
{
  "instances": [
    {"category": "ship", "geometry": "polygon",
     "polygon": [[x1,y1], [x2,y2], ...], "confidence": 0.9}
  ],
  "none": false
}
规则：
1. 坐标系：图像左上角为 (0,0)，右下角为 (1000,1000)，坐标一律用 [0,1000] 内整数
2. geometry 三选一：polygon（最多 24 个顶点，逆时针，贴合目标边界）；
   box（左上 x,y + 宽 w + 高 h，适合储油罐/矩形建筑等简单形状）；
   point（单个中心点，仅用于极小目标）
3. 每个显著目标一个实例（与提示词一一对应，最多 5 个），按显著性降序排列
4. 若图中无显著目标，输出 {"instances": [], "none": true}
5. 顶点必须闭合且不自交；禁止输出文字解释
```

### 2.3 Pass 2.5 Zoom-in 精修模板（可选，边界精度的关键）

```
下图是从遥感图像中裁剪并放大的局部区域（放大 2 倍）。
局部坐标系同样为左上角 (0,0)、右下角 (1000,1000)。
请为裁剪区域内【唯一】的显著目标输出更精细的多边形
（最多 24 个顶点，逆时针，贴合目标真实边界），JSON 格式与之前相同。
```

> Zoom-in 的正确用法：先用 Pass 2 的 box 裁出目标邻域（向外扩 20%）→ 放大 2 倍 → 局部多边形 → 坐标映射回全图。这是"大模型掩码"能达到像素级精度的**唯一靠谱路径**，实验里作为 R2 级消融。

### 2.4 调用协议（工程参数）

| 参数 | 值 | 理由 |
|------|-----|------|
| 模型 | `deepseek-v4-flash-vision-exp`（等价 `deepseek-flash`） | 与 v1 相同，价格最低 |
| temperature | 0 | 坐标输出必须确定 |
| JSON Output | `response_format={"type":"json_object"}` | 可解析 |
| 图片 | 原始分辨率 base64（默认缩到 ～1300×1300），detail="high" | 坐标质量 > 512 低清；zoom-in 必须高清 |
| max_tokens | **16000**（试点实测校准：该模型思考模式会消耗输出预算，1200 时约 3/4 的 Pass2 调用因思考占满预算返回空内容） | 重推理任务 |
| system 消息 | "直接输出最终 JSON，禁止逐步推理"（代码常量 SYSTEM_V2） | 思考 token 实测 -31% |
| 解析容错 | content 带多余文字/代码块时自动提取首个 JSON 对象（_extract_json） | 应对思考泄漏到 content 的回复 |
| 重试 | 失败重试 3 次；JSON/坐标校验不通过 → 重新调用 | 幻觉兜底 |
| 坐标校验 | 全部落在 [0,1000]；多边形顶点数 3～24；box 的 w/h > 0 | 渲染前硬校验 |

### 2.5 坐标幻觉的工程对策（本方法最大的坑，务必全部落实）

1. **归一化坐标 [0,1000]**：不让模型数像素（352×352 的坐标空间太小，模型数不清），[0,1000] 是大模型最熟悉的视觉坐标协议。
2. **两段式链**：先语义后几何，比一步到位吐坐标的成功率高得多（试点验证）。
3. **禁止相对词**：模板明确"禁止文字解释"，防止"略偏左"这种不可渲染的输出。
4. **自检回合**（阶段3）：把渲染图回喂，让模型自己看出"多边形偏了/漏了"，输出修正 JSON。
5. **回退链**：polygon 校验失败 → 用该实例的 box → 实例级失败 → 丢弃该实例 → 全部失败 → "none"（全零图）。
6. **失败清单**：所有校验失败的图进人工清单，报告"几何输出合格率"（预期 >90%，写进论文 limitation 也可）。

## 第 3 章 阶段2：掩码渲染器（确定性、零参数、可微可选）

本地实现 `utils/rasterize.py`，输入坐标 JSON，输出显著图 S ∈ [0,1]^{H×W}。**无任何学习参数、不读原图。**

### 3.1 三种几何的硬渲染（推理用）

| geometry | 渲染方式 | 备注 |
|----------|---------|------|
| polygon | 扫描线多边形填充（even-odd），内部 1、外部 0 | `skimage.draw.polygon` 或 `cv2.fillPoly` |
| box | 矩形填充 | 宽高直接由 JSON 给出 |
| point | 高斯圆盘（σ 与目标尺度挂钩，默认 8～12 像素） | 小目标专用 |
| none | 全零图 | ORSI-SOD 存在无显著目标样本 |

多实例：**并集**（显著图 = ∪ 各实例掩码；每实例默认二值 1，可乘以 confidence 得到软显著图——置信度乘子作为消融）。

### 3.2 软渲染（可微，用于可选校准阶段）

把"多边形填充"换成有符号距离函数 + sigmoid：

```
d(p)  = 点到多边形边界的有符号距离（内部为正）
S(p)  = σ(α · d(p))          α 是锐度参数（如 α=2/像素）
```

- 优点：对顶点坐标**可微**，若后续想用 GT 微调坐标/置信度，梯度可回传；
- 缺点：边界 1～2 像素的软过渡会让 MAE 略差于硬二值——消融"硬 vs 软"。
- 主实验默认**硬渲染**（指标口径与二值 GT 最匹配）。

### 3.3 渲染器在论文里的定位（防审稿人）

> "渲染器是一个无参数、无视觉输入的几何绘制程序，等价于绘图仪的笔。显著图的**内容**（画什么、画在哪、画多大）100% 由 DeepSeek 多模态大模型决定。因此本文称'最终显著图由多模态大模型生成'是准确的；渲染器不构成任何视觉推理。"

## 第 4 章 阶段3：MLLM 自修正闭环（验证-修正，全程 LLM）

v1 的闭环是"LLM 诊断 + CNN 修正模块"；v2 的闭环**全在大模型内部**——渲染图回喂，模型自己改自己的掩码。这是 v2 最亮的卖点之一（**"大模型既当画家又当自己的裁判"**）。

### 4.1 流程

```
S（初版显著图）──► 半透明红叠加原图 ──► DeepSeek ──► 修正 JSON ──► 重渲染 → S¹
（可选再来一轮 → S²；实验证明 1 轮即可，论文用 1 轮）
```

### 4.2 修正提示词模板（SelfCheck）

```
这是同一张遥感图像，红色半透明区域是当前显著图的渲染结果。
请找出错误并输出修正，严格按 JSON：
{
  "add":    [{"category": "ship", "geometry": "polygon", "polygon": [...], "confidence": 0.8}],
  "remove": [1],
  "refine": [{"index": 0, "geometry": "polygon", "polygon": [...]}]
}
规则：
- add：当前显著图中【漏掉】的显著目标（0～3 个，格式与掩码生成阶段一致）
- remove：应当删除的实例编号（按当前显著图从 1 开始的实例序号）
- refine：需要替换几何形状的实例编号 + 新几何
- 若显著图已正确，三项均为空数组
```

### 4.3 修正合并逻辑（本地确定性）

1. 删除 `remove` 指定的实例；
2. `refine` 用新几何替换对应实例；
3. `add` 追加新实例；
4. 重新并集渲染 → S¹。

## 第 5 章 阶段4（可选）：可微校准——整个方法唯一"可训练"的部分

**问题**：纯零训练的方法，审稿人可能质疑"没有学习过程算不算方法贡献"。

**对策**：保留一个**极轻量的校准阶段**，但明确它与"生成"无关、只调"渲染参数"：

| 校准对象 | 参数 | 训练信号 |
|----------|------|---------|
| 置信度映射 | 每个置信度区间一个标量（～5 个） | 验证集 Sα/Fβ 最大化 |
| 软渲染锐度 α | 1 个标量 | 同上 |
| point 的 σ | 1 个标量 | 同上 |

- 总计 **<10 个可训练标量**，在 50～100 张验证图上用网格搜索/坐标下降即可，**不需要反向传播、不需要 GPU**；
- 论文叙事：*"the only learnable components are a handful of rendering hyper-parameters calibrated on a 100-image validation set, consuming no gradient-based training."*
- 消融：无校准（默认参数）vs 校准后，预期增益 ≤0.5% Sα——如实报告，反而证明"增益来自大模型而非校准"。

## 第 6 章 完整推理协议（伪代码）

```python
def ds_sod_v2(image: np.ndarray, rounds: int = 1) -> np.ndarray:
    # 阶段1a：AI 生成提示词
    prompt = call_llm(PROMPTGEN_PROMPT, image)          # 显著性命题 JSON
    # 阶段1b：DS 多模态大模型生成掩码
    mask_json = call_llm(MASKGEN_PROMPT.format(prompt), image)
    mask_json = validate_geometry(mask_json)            # 坐标/顶点/实例硬校验
    # 阶段2：确定性渲染
    S = rasterize(mask_json, image.shape)               # 多边形填充 → 显著图
    # 阶段3：MLLM 自修正闭环
    for _ in range(rounds):
        overlay = render_overlay(image, S)              # 半透明红叠加
        fix = call_llm(SELFCHECK_PROMPT, overlay)
        S = rasterize(merge(mask_json, fix), image.shape)
    return S
```

**推理成本**：每图 2 次调用（Pass1+Pass2）；R1 加 1 次；zoom-in 每个实例加 1 次。**零 GPU、零训练、纯 API。**

## 第 7 章 实验设计

### 7.1 数据集 / 指标（与 v1 完全一致）

- ORSSD（800）、EORSSD（2000）、ORSI-4199（4199）；测试集 200/600/2199。
- 指标：Sα、Fβ_max/Fβ_mean、Eξ_max/Eξ_mean、MAE（复用 `eval/metrics.py`）。
- 场景分组评测：复用 v1 先验库的 `challenge_tags`（或 Pass 1 新生成的标签）。

### 7.2 方法变体定义（论文主表 + 消融都要）

| 变体名 | 组成 | 用途 |
|--------|------|------|
| DS-SOD-Zero | Pass1+Pass2+硬渲染，无闭环无 zoom | 主方法（零训练） |
| DS-SOD-R1 | +1 轮自修正 | 闭环消融 |
| DS-SOD-Zoom | +zoom-in 精修 | 边界精度消融 |
| DS-SOD-Full | +自修正 +zoom-in | 完整方法上限 |
| DS-SOD-Hybrid | MaskGen 提示词 → SAM2 解码掩码 | 路线②对照（LLM 提示 + 视觉解码器能否更强） |

### 7.3 对比方法（沿用 v1 清单）

CNN 代（MCCNet/ACCoNet/CorrNet/ERPNet）、Transformer 代（GeleNet/VST/ICON/MRBINet）、大模型/扩散代（SAM2-RS/IPDiff）、2026 文本融合工作 1～2 个。

### 7.4 消融主线（决定论文高度）

| # | 消融 | 假设 |
|---|------|------|
| 1 | 一步到位吐坐标 vs 两段式链（PromptGen→MaskGen） | H2：AI 生成提示词的价值 |
| 2 | point vs box vs polygon vs polygon+zoom | H3：几何粒度贡献 |
| 3 | 自修正 0/1/2 轮 | H4：自我裁判闭环有效 |
| 4 | 硬渲染 vs 软渲染；confidence 乘子 on/off | 渲染细节稳健性 |
| 5 | 模型规模：flash vs 更大模型 | H7：精度-成本曲线 |
| 6 | DS-SOD-Full vs DS-SOD-Hybrid(SAM2) | 视觉解码器是否必要 |
| 7 | GeleNet+SPIM（v1 路线）vs DS-SOD-Zero | **新旧范式对决**：CNN 训练 vs 大模型零样本 |

### 7.5 假设清单与成败标准（先写死）

| 假设 | 内容 | 实验 |
|------|------|------|
| H1 | MLLM 仅凭"看图+语言"零训练生成达到竞争水平的显著图 | 主实验 7.3 |
| H2 | AI 链式生成的提示词显著优于一步到位的坐标输出 | 消融 #1 |
| H3 | 几何粒度 monotonic：point < box < polygon < +zoom | 消融 #2 |
| H4 | 自修正闭环提升精度 | 消融 #3 |
| H5 | 增益集中在语义难例（低对比/同谱异物/小目标） | 场景分组 |
| H6 | 达到/接近 SOTA 且总成本（API 美元 + 零 GPU）优势明显 | 主实验 + 成本表 |
| H7 | 精度随模型规模单调、成本可接受 | 消融 #5 |
| H8 | 跨数据集零样本泛化（无需任何训练/适配） | 跨集直接评测 |

**成败标准**：
- ✅ 成功：DS-SOD-Full 三数据集与 GeleNet/IPDiff 同区间（Sα 差距 ≤3%），且难例子集领先 + 零训练叙事成立 + H2/H4 消融成立；
- ⚠️ 部分成功：整体弱于 SOTA 但难例子集明显领先 + 成本/时间优势 → 叙事转"零训练 + 语义难例专精 + 可解释"；
- ❌ 失败兜底：坐标质量极差（合格率 <70%）→ 降级回 v1（CNN 主干 + LLM 先验）作为主体，v2 作为"limitation 与未来方向"写进论文（诚实且可收场）。

## 第 9 章 公平性与成本声明（写进论文实验节）

1. DeepSeek 仅接收图像与自渲染图，**从未接触任何 GT**；
2. 全部提示词模板、mask_bank.json、渲染器、评测脚本开源；
3. 渲染器无学习参数、无视觉输入——显著图内容全部来自大模型输出；
4. 对比方法数值优先引用原论文，无法对齐用官方代码复现并注明；
5. API 花费、每图 tokens、延迟、调用轮数如实报告；
6. 模型版本与日期写进脚注（`deepseek-v4-flash-vision-exp`）。

**成本估算**（写进论文成本节，2026-09 试点实测校准）：
- 实测单次调用输出：Pass1 ≈ 2～4K tokens、Pass2 ≈ 8～12K、SelfCheck ≈ 6～10K（思考模式占大头）；
- 全量 7000 图 × 3 次调用 ≈ 21k 调用 × 平均 ～20K 输出 tokens ≈ 420M tokens → **按 flash 输出 $0.6/1M 计 ≈ $250 上限、$100～150 量级**；
- **降本选项**（论文成本节逐条报告）：① 只跑测试集（2999 图）→ ≈$40～60；② 消融用子集抽样；③ 相同模板前缀触发 prompt cache（试点已观察到缓存命中）；④ 输出预算 16000 只给 Pass2，Pass1 用 8000；
- 对比：v1 需要 44 epoch × 3 数据集 GPU 训练（数天电费）+ 人工调参；v2 只需 **API 费用 + 零 GPU**。费用是"按需付费"，且 mask_bank 缓存后评测零成本。

## 第 10 章 论文叙事（把技术变成故事）

- **标题备选**：
  - 《Mask-as-Text: When a Multimodal Large Language Model Generates Saliency Maps for Optical Remote Sensing Images》
  - 《From Training Pixels to Asking a Model: Zero-Training Salient Object Detection via DeepSeek-Generated Geometric Masks》
- **引言主线**：四代方法（CNN→Transformer→基础模型→扩散）都在"挖图像"，本文第一次让**会看会想的 MLLM 直接生成显著图**——显著图第一次成为"语言输出"。
- **方法节三支柱**：① 链式提示词生成（PromptGen→MaskGen）；② 确定性掩码渲染（零参数画笔）；③ 自我裁判闭环（SelfCheck）。
- **实验节杀手锏**：**零训练 vs 全训练**的对决表（DS-SOD-Zero 不碰 GT、不训任何网络，与 44 epoch 训练的 GeleNet 同表对比）；难例子集领先；成本表"$7 vs 数天 GPU"。
- **结论**：ORSI-SOD 进入"问模型要显著图"的时代；本框架主干无关（把 DeepSeek 换成任何 MLLM 都成立）——这是最强的可扩展性声明。
